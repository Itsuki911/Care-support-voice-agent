更新日: 2026-11-18

本計画はユーザーとのブラッシュアップで合意した要件を記録する。機能実装の完了報告ではない。

## 目的と検証環境

- 現段階は用途を介護に限定しない、汎用の音声agentの機能検証とする。
- 手元のPCで起動できた既存アプリを出発点に、ローカルで段階的に検証する。
- UIとPython agentはローカルで動かす。LiveKit Cloud、OpenRouter、STT/TTS、Langfuseへの接続は引き続き外部サービスを利用する。完全オフライン化は目的にしない。
- 最初の利用者は1人を想定し、データにはユーザーとセッションの識別子を持たせる。
- PostgreSQLで長期記憶を検証し、Markdownのローカル文書からRAGを始める。
- 将来のGCP Memory Bankへの移行時に互換性と設計を再検討する。今回の段階でGCP互換層を作ることは必須にしない。
- Gmail機能の拡張、GCP移行、対応文書形式の拡大、クラウド公開の拡張は初期検証の必須項目にしない。

## 合意した会話方針

| 項目 | 方針 |
| --- | --- |
| ツール選択 | 依頼内容とツール定義をもとにLLMが決める。不要なツールは呼ばない |
| 外部操作 | 人の許可を得てから実行する。LLMによる選択を許可の代わりにしない |
| 回答の長さ | 1回の回答は最大3文。確認質問・進捗の発話も短くする |
| 不明な情報 | 最初に一度、必要な情報を人へ質問し、根拠のある回答につなげる |
| 質問後も不明な場合 | 推測で補完せず、分からない範囲を伝える。確認を繰り返して会話を止めない |
| 根拠 | 回答の裏付けには利用するが、出典の読み上げ・第三者への提示を必須にしない |
| 会話の自然さ | 処理説明や長い列挙を避け、口頭で理解できる回答にする |
| 記憶 | 好み・基本情報・継続中の話題を長期記憶の初期対象にする |

「出典を毎回表示する」という初期案は、最終合意に合わせて必須要件から外した。
検索結果の出所は内部で保持し、検証画面や要求時に確認できるようにする。

## 実装の順序

レベル0 → レベル1 → レベル2 → レベル3A（Markdown RAG）→ レベル4のローカル機能表示。
その後、レベル3B（Web検索）とレベル4のWeb検索表示を追加する。
進捗イベントの設計はレベル1から始め、メモリ・RAG実装時に発行処理を追加する。

各段階で基準を満たしてから次へ進む。機能の有無だけでなく、会話品質・遅延・費用の変化も確認する。
本計画の保存では、既存agent・UI・デプロイ設定の動作は変更しない。
